# Working with this repo

## Reporting style

The project owner is not a developer. When reporting findings, investigations,
or the result of a task:

- Always lead with a plain-English summary: what's actually happening, and
  what it means for a member (a real person using the app) — before any
  technical detail.
- Put file paths, line numbers, and code below that summary, as reference
  material, not above it.
- This applies to bug reports, test results, and status updates alike.
